## 二、功能模块总览

> 当前为 v3.0 版本，已实现登录认证、权限控制、账号管理、短剧全生命周期管理、
> 智能广告投放算法、事件回传、用户画像等完整功能。

### 模块 0：登录认证

**定位**：系统入口，负责用户身份验证和会话管理。

#### 0.1 登录页
- 独立全屏页面（不走 BasicLayout），路由 `/login`
- 用户名 + 密码表单，浮动 Label 交互
- 密码明文/密文切换
- 登录失败抖动动画 + 错误提示
- 粒子动画背景（Canvas 实现，鼠标交互）
- 登录成功后 token 存入 `localStorage`，跳转仪表盘

#### 0.2 认证流程
- 路由守卫：未登录（无 token）→ 强制跳转 `/login`
- Axios 请求拦截器自动注入 `Authorization: Bearer <token>` + `clientid` 请求头
- 响应拦截器：`401` → 清除 token/refresh_token/client_id + 跳转登录页
- 退出登录：调用 `/auth/logout`，清除本地状态（token/client_id/accountStore/appStore）

### 模块 1：短剧管理

**定位**：平台内容资产的核心管理入口，负责短剧的全生命周期管理及首页运营位配置。

#### 1.1 短剧列表
- 路由：`/drama/list`，权限：`canManageDrama`
- 分页展示所有短剧（封面、名称、标签、集数、解锁模式、广告规则、创建时间）
- 名称模糊搜索
- 标签筛选（按标签名称单选过滤）
- 解锁模式标签：仅广告（绿）/ 仅付费（橙红）/ 广告或付费（蓝）
- 广告推送规则关联展示（每N广告解锁N集，每日上限）
- 点击名称跳转详情
- 删除操作（二次确认，含关联数据检查：剧集/标签/首页展位/广告规则）
- 切换应用时自动刷新列表
- `keep-alive` 缓存组件

#### 1.2 上传短剧
- 路由：`/drama/upload`，权限：`canManageDrama`
- 两阶段交互流程：
  - **阶段一（组织文件）**：填写基本信息 + 添加/排序视频文件
  - **阶段二（上传进度）**：实时展示每个文件的上传状态和进度
- 基本信息表单：
  - 短剧名称（必填，2–50 字符）
  - 短剧描述（选填，最多 500 字符）
  - 标签选择（多选，按分组展示）
  - 解锁模式选择（IAA_ONLY / IAP_ONLY / IAA_IAP）
  - 广告推送规则关联（下拉选择已启用的规则）
  - 免费集数设置
- 视频文件管理：
  - 拖拽或点击上传（支持 mp4 / mov，单文件不超过 2GB）
  - 按文件名自动排序
  - 拖拽行调整顺序、上下移动、删除
- 上传引擎：`tt-uploader` / `@byteplus/uploader` SDK
  - STS Token 鉴权（通过 `/vod/upload-session` 获取）
  - 分片上传，支持暂停/恢复/重试
  - 实时进度百分比 + 速度显示
  - 完成后返回 Vid（视频ID）和 PosterUri

#### 1.3 短剧详情
- 路由：`/drama/:id`，权限：`canManageDrama`
- 基本信息卡片：名称、集数、创建时间、标签、描述、解锁模式
- 集数列表 + 内嵌视频播放器（BytePlus VePlayer）
- 集数 Tab 切换，未解锁集显示锁定状态
- 视频时长格式化显示

#### 1.4 短剧标签管理
- 路由：`/drama/tags`，权限：`canManageDrama`
- 标签 CRUD（名称 + 分组 + 颜色 + 排序权重 + 状态）
- 分组 Tab 筛选（全部 / 按分组名过滤）
- 默认分组：题材、风格、受众（支持自定义输入新分组）
- 行内 Switch 启用/禁用标签
- 关联短剧数量展示（`refCount`）
- 删除时提示关联短剧数

#### 1.5 首页轮播管理
- 路由：`/drama/home-banner`，权限：`canManageDrama`
- 管理 TikTok Minis 首页轮播推荐短剧（最多 8 张）
- CRUD + 排序调整（上移/下移）
- 关联短剧选择（搜索下拉）
- 轮播标题、封面图 URL
- 行内 Switch 控制展示/隐藏
- 统一 HomeSlot 模型（slotType=BANNER）

#### 1.6 首页热播短剧
- 路由：`/drama/home-hot`，权限：`canManageDrama`
- 管理首页热播短剧模块
- CRUD + 排序调整
- 排名徽章（前三名金/银/铜色）
- 行内 Switch 控制展示/隐藏
- 统一 HomeSlot 模型（slotType=HOT）

#### 1.7 首页分类排行榜
- 路由：`/drama/home-rank`，权限：`canManageDrama`
- 管理各分类短剧排行榜（每个分类最多 10 条）
- 8 个固定分类：甜宠、霸总、逆袭、玄幻、都市、古装、悬疑、喜剧
- 分类 Tab 切换，显示各分类启用条数（RankCategoryStat）
- CRUD + 排名调整（上移/下移）
- 排名徽章（前三名金/银/铜色）
- 行内 Switch 控制展示/隐藏
- 统一 HomeSlot 模型（slotType=RANK）

#### 1.8 更多短剧（Explore）
- 路由：`/drama/home-explore`，权限：`canManageDrama`
- 管理首页"更多短剧"模块的展示内容

#### 1.9 广告推送设置（短剧维度）
- 路由：`/drama/ad-settings`，权限：`canManageDrama`
- 管理短剧级别的广告推送规则
- 规则参数：每N广告解锁N集、每日广告上限
- 规则启用/禁用、默认规则标记
- `keep-alive` 缓存组件

#### 1.10 渲染顺序设置
- 路由：`/drama/module-order`，权限：`canManageDrama`
- 管理首页各模块（轮播/热播/排行榜/更多）的渲染顺序

### 模块 2：用户管理

**定位**：运营人员了解用户行为、分析用户质量的核心工具。

#### 2.1 用户列表
- 路由：`/user/list`，权限：`canViewUser`

- 点击行跳转用户详情
- 切换应用时自动刷新列表
- `keep-alive` 缓存组件

#### 2.2 用户详情（数据画像）
- 路由：`/user/:id`，权限：`canViewUser`
- 基础信息卡片：头像、昵称、注册时间、最后活跃时间、价值分层（valueTier）
- 8 项行为指标卡片（4×2 网格）：

### 模块 3：应用管理（切换应用）

**定位**：支持多 TK Minis 应用的数据隔离与快速切换，是全局数据上下文的控制中心。

#### 3.1 应用列表 / 切换
- 路由：`/system/app`，权限：`canSwitchApp`（仅管理员）
- 卡片式展示所有应用（首字母头像、名称、运行状态、应用类型）
- 点击切换当前工作应用，全局数据随之刷新
- 当前应用高亮标识 + 渐变顶部边线
- 切换后自动跳转仪表盘
- 应用信息：appName / appType / clientKey / dailyEventQuota / featureFlags

#### 3.2 顶部导航栏快捷切换
- `AppSwitcher` 组件（下拉菜单，仅 `canSwitchApp` 权限可见）
- 非 admin 用户显示当前应用名（只读，绿色状态点）
- 切换后自动跳转仪表盘

#### 3.3 数据隔离机制
- 后端通过 Sa-Token Session 存储当前 clientKey
- 前端调用 `POST /system/application/switch` 切换应用
- 切换后后端将 clientKey 写入 Session，后续所有 SQL 自动拼接 `WHERE app_id = ?`
- 前端不在请求参数中传递 clientKey（由后端 Session 自动获取）

### 模块 4：广告管理

**定位**：管理 TK Minis 平台内的广告资源，配置广告触发策略，智能投放算法，事件回传，最大化广告收益。

#### 4.1 广告库存列表
- 路由：`/ad/list`，权限：`canManageAd`
- 分页展示所有广告（规则名称、广告位 ID、类型、推送次数、激活状态、更新时间）
- 行内 Switch 切换激活状态（启用/禁用 API）
- 广告类型标签：激励视频（`RewardedVideoAd`）、插屏广告（`InterstitialAd`）
- 编辑（Modal 表单）、删除（二次确认）
- `keep-alive` 缓存组件

#### 4.2 广告推送规则
- 路由：`/ad/push-settings`，权限：`canManageAd`
- 推送规则 CRUD
- 规则参数：
  - 规则名称
  - 每次解锁需观看广告数（adCountPerUnlock）
  - 每次解锁的集数（episodesPerUnlock）
  - 每日广告上限（maxAdCountPerDay，0=不限）
  - 是否默认规则（isDefault）
- 行内启用/禁用开关

#### 4.3 事件回传规则
- 路由：`/ad/callback-rules`，权限：`canManageAd`
- 按短剧维度配置事件回传规则
- 支持 IAP 标准事件（9 个）：
  - video_play_request / ep_play / add_to_wishlist / start_unlock
  - complete_watching / unlock_panel_show_request / unlock_panel_show
  - unlock_panel_click / unlock_success
- 支持 IAA 标准事件（3 个）：
  - video_play_request / ep_play / minis_ad_show
- 每个事件可配置：启用/禁用、回传比例（callbackRatio）
- 批量保存配置

#### 4.4 回传日志
- 路由：`/ad/callback-logs`，权限：`canManageAd`
- 分页展示回传执行日志
- 日志字段：事件类型、回传URL、请求体、响应码、状态、重试次数、耗时
- 状态标签：待执行(橙) / 成功(绿) / 失败(红) / 重试中(橙) / 已放弃(灰)
- 手动触发重试补偿按钮

#### 4.5 算法分析（智能投放）
- 路由：`/ad/analytics`，权限：`canManageAd`
- 广告效果分析面板
- 时间窗口切换：24H / 7D / 30D
- 指标：推送次数、完成次数、完成率、解锁次数、转化率
- 风险标签展示（riskTag）

#### 4.6 算法状态
- 路由：`/ad/algorithm-status`，权限：`canManageAd`
- 算法运行阶段展示：冷启动（COLD_START）/ 正常（NORMAL）
- 冷启动阈值与当前 Epsilon 值
- 冷启动广告列表（7日推送次数）
- TOP10 广告排行（finalScore + scoreMatrix 多维评分）

#### 4.7 推送日志
- 路由：`/ad/push-logs`，权限：`canManageAd`
- 分页查询广告推送执行日志
- 筛选：openId / adId / 时间范围 / 解锁状态 / 嫌疑标记
- 日志字段：用户、广告、短剧、集数、观看状态、观看秒数、是否嫌疑、嫌疑原因、解锁结果

#### 4.8 算法参数配置
- 路由：`/ad/algorithm-config`，权限：`canManageAd`
- 算法全局开关（isEnabled）
- Epsilon 参数：冷启动 / 正常阶段
- 冷启动参数：最小曝光基数 / 冷启动因子
- 时间窗口权重配置：5分钟 / 30分钟 / 2小时 / 24小时 / 7天
- 多维度评分配置：维度代码 / 维度名称 / 权重 / 启用状态 / 计算器 Bean

## 三、全局约定

### 3.1 数据隔离
- 所有业务数据以 `clientKey`（TikTok Minis 应用标识）为维度隔离
- 后端通过 Sa-Token Session 存储当前 clientKey，SQL 拦截器自动拼接 `WHERE app_id = ?`
- 前端调用 `POST /system/application/switch` 切换应用
- 前端不在请求参数中传递 clientKey（由后端 Session 自动获取）
- 路由守卫：未选应用时，admin 强制跳转应用列表页；非 admin 自动选择第一个应用

### 3.2 接口规范
- 统一响应格式：`{ code: number, data: T, msg: string }`
- Axios 响应拦截器自动解包：`code === 0 || code === 200` 时返回 `data`，否则 `Message.error`
- 分页参数：`pageNum`（从 1 开始）、`pageSize`
- 分页响应格式：`{ rows: T[], total: number }`
- 时间格式：ISO 8601 `YYYY-MM-DD HH:mm:ss`
- 错误码：`0` / `200` 成功，非 `0` 失败，`401` 未登录，`403` 无权限
- 错误处理：认证接口不弹全局错误提示，其他接口统一 `Message.error`
- 请求头：`Authorization: Bearer <token>` + `clientid: <client_id>`

### 3.3 前端架构约定
- 页面组件：`src/views/<module>/`
- 公共组件：`src/components/`（AppSwitcher / EmptyState / GlobalLoading / Nav / ResizableTable）
- API 层：`src/api/<module>.ts`，只做请求，不含业务逻辑
- Store：`src/stores/<module>.ts`，管理列表分页状态
- 类型定义：`src/types/<module>.ts`
- 工具函数：`src/utils/`（request / echarts / format / vod-uploader / vod-url）
- Composables：`src/composables/`（useVideoUpload / useAsyncLock / useResizableColumns）
- ECharts 统一按需引入，入口：`src/utils/echarts.ts`
- Mock 数据：`src/mock/<module>.ts`
- 布局：`src/layouts/BasicLayout.vue`（侧边栏 + 顶部导航 + 内容区）
- 样式：`src/styles/`（global.css + tokens.css）

### 3.4 路由结构
```
/                        → 重定向 /dashboard
/login                   → 登录页（public，不走 BasicLayout）
/403                     → 无权限提示页
/dashboard               → 仪表盘（canViewDashboard）
/drama/list              → 短剧列表（canManageDrama）
```

### 3.6 Arco Design 组件使用规范（强制）

> 以下规则来自实际踩坑，违反会产生 Vue warn 或运行时异常。

#### 3.6.1 `a-statistic` — value 类型限制
- ❌ 禁止将字符串传给 `:value` prop（只接受 Number | Object）
- ✅ 字符串类型指标用自定义 div 渲染，样式对齐 Statistic

#### 3.6.2 `a-statistic` — prefix / suffix 使用方式
- ❌ `prefix` 不是 prop，禁止 `prefix="$"`
- ✅ `prefix` 用具名插槽 `<template #prefix>$</template>`
- ✅ `suffix` 是 prop，可直接传字符串

#### 3.6.3 API 返回值解构规范
- 分页接口返回 `{ rows: T[], total: number }`
- 调用方必须解构后再赋值，不能把整个响应对象赋给数组 ref

#### 3.6.4 ECharts 实例生命周期规范
- `initChart` 必须在 `onMounted` + `nextTick` 之后调用
- `onUnmounted` 中必须 `dispose()` + 移除 resize 监听

#### 3.6.5 Mock 正则匹配顺序规范
- 详情/子资源路由必须在列表路由之前注册
- 所有 Mock 正则末尾统一使用 `(\?.*)?$`

#### 3.6.6 `a-badge` status 合法值
- 只接受：`normal` / `processing` / `success` / `warning` / `danger`
- ❌ 不存在 `"default"`

#### 3.6.7 `a-range-picker` placeholder 必须是数组
- ✅ `:placeholder="['开始日期', '结束日期']"`

#### 3.6.8 禁止使用不存在的 Arco Design 图标
- ❌ `icon-pie-chart` → 用 `icon-bar-chart` 替代

### 3.7 UI 设计规范

- 深色主题（TikTok 体系设计），霓虹质感
